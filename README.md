## 🧠 Core Concepts

StockSense AI is built around four core analytical primitives that drive every feature in the platform:

### 1. AI Signal (`Bullish` / `Neutral` / `Bearish`)
Every stock receives a directional trading signal generated by the backend AI engine. The signal is derived from price momentum, volume patterns, and trend analysis. The frontend renders each signal with semantic color coding (green / gold / red) and consistent `SignalTag` components across all views.

### 2. AI Confidence Score (0–100%)
A scalar score representing the AI's certainty in its own signal. Rendered as an animated SVG `ConfidenceRing` — a custom-built, fully accessible donut chart that fills via a CSS stroke-dashoffset animation. High-confidence setups (≥75%) are labelled "Strong"; others are "Moderate."

### 3. Smart Price Levels
For each stock, the AI engine computes four key price levels:
- **Support** — the floor where buying pressure is expected
- **Resistance** — the ceiling where selling pressure is expected
- **Breakout** — a projected trigger point for momentum acceleration
- **AI Target (30d)** — a 30-day price target generated by the model

### 4. Market Bias
A macro-level snapshot showing the signal distribution (Bullish / Neutral / Bearish) across the entire tracked universe. Displayed as a ranked panel on every Stock Detail page and aggregated into the Daily AI Outlook on the Dashboard.

## 📡 Data Sources — Twelve Data & Simulated Mode

This is one of the most important architectural decisions in the platform, and it is handled with full transparency to the user.

### How It Works

The backend connects to the **[Twelve Data API](https://twelvedata.com)** — a professional financial data provider — to fetch real-time US equity prices, OHLCV history, and market status. Each `Stock` object returned by the API includes a `dataSource` field:

```ts
export interface Stock {
  // ...
  dataSource: "Twelve Data" | "simulated";
}
```

### Why Two Modes?

| Mode | When It Activates | What It Means |
|------|-------------------|---------------|
| **`"Twelve Data"`** | Twelve Data API key is configured and market is accessible | Prices are **real, live market data** from US exchanges |
| **`"simulated"`** | No API key configured, rate limit hit, or market is closed | Prices are **algorithmically generated** by the backend to maintain a realistic, demo-friendly experience |

### Frontend Transparency

Whenever a stock is in simulated mode, the Stock Detail page renders a **visible amber warning badge**:

```
⚠ Simulated prices
```

This is intentional. Rather than hiding the limitation, the frontend surfaces it clearly — a design decision that reflects engineering honesty and production-thinking. Recruiters and evaluators can see that the system gracefully degrades without breaking the UX.

The `getMarketStatus` API endpoint also exposes `mode`, `provider`, `configured`, `stocksWithPrices`, and `lastPriceRefresh` — all consumed by the frontend for transparency panels.

### Price History
Historical charts (`/api/stocks/:symbol/history`) support four time ranges:

```ts
export type Range = "1D" | "1W" | "1M" | "1Y";
```

The chart data is `{ label: string; price: number }[]` — clean, normalized, and immediately renderable by Recharts with no transformation needed on the frontend.

```
StockSense AI Frontend
│
├── Next.js 14 (App Router)       — SSR/SSG, file-based routing, layouts
├── TypeScript 5.6                — Full type safety, single source of truth types

├── Sonner 2.0                    — Toast notification system
├── Lucide React                  — Supplemental icon set

```

### Why These Choices

| Decision | Rationale |
|----------|-----------|
| **Next.js App Router** | Enables Server Components for landing page (instant FCP), Suspense boundaries for progressive loading, and middleware-based route rewrites |
| **RTK Query over React Query** | Tight Redux integration, automatic tag-based cache invalidation across mutations, eliminates boilerplate fetch code, `keepUnusedDataFor: 300` for 5-minute smart caching |
| **Custom SVG ConfidenceRing** | No third-party chart library needed for the core AI metric — full control over animation, accessibility, and size |
| **Tailwind with custom tokens** | Design consistency enforced at the config level: `gold`, `up`, `down`, `mute`, `panel`, `line` — prevents color inconsistency across 60+ components |
| **Recharts AreaChart** | Lightweight, composable, and SSR-safe. The gradient fill and custom tooltip match the dark theme without overriding library defaults |

## 🔄 State Management Deep-Dive

### Store Architecture

```
Redux Store
├── user (userSlice)
│   ├── token: string | null       — JWT Bearer token
│   └── user: AuthUser | null      — Full user object with role, plan, etc.
│
└── baseApi (RTK Query)
    ├── Cache: Stock, Watchlist, Alerts, Plans, Dashboard...
    └── Tags: 12 cache tags for surgical invalidation
```

### RTK Query Configuration

```ts
// baseApi.ts — Key settings
keepUnusedDataFor: 300,     // 5-minute cache retention
refetchOnFocus: false,      // No refetch on window focus (intentional)
refetchOnReconnect: true,   // Auto-refetch on network reconnect
```

**JWT Auto-Injection**: The `prepareHeaders` interceptor reads the token from Redux state first, then falls back to `localStorage` — supporting both SSR hydration and client-side navigation seamlessly.

### Session Persistence

```ts
// userSlice.ts — Dual storage strategy
setSession()  → writes to Redux state AND localStorage (ss_token, ss_user)
clearSession() → clears both
// On app init: state hydrated from localStorage, zero loading flash
```

### Cache Invalidation Tags

The `baseApi` declares 12 cache tags. Mutations automatically invalidate relevant tags:
- Adding/removing from watchlist → invalidates `Watchlist` + `Dashboard`
- Creating an alert → invalidates `Alerts` + `Dashboard`
- Admin blocking a user → invalidates `AdminUsers`
- Completing a checkout → triggers session refresh + `Billing` refetch

## 🔐 Authentication System

### Three Auth Paths

```
1. Email/Password ──→ POST /api/auth/login
                   ──→ POST /api/auth/signup

2. Google OAuth ────→ Google Identity Services (GSI) SDK
                   ──→ POST /api/auth/google (credential token)

3. Password Reset ──→ POST /api/auth/forgot-password
```

### Role-Based Routing

After login, the `AuthForm` reads `user.role` from the response:
```ts
router.push(user.role === "admin" ? "/admin/users" : "/dashboard");
```

`AuthGuard` wraps all protected routes — it reads from Redux state and redirects unauthenticated users to `/login`.

### Google Identity Services Integration

The app manually loads the GSI script, initializes it with the client ID, and renders the native Google button in a hidden overlay div. A styled custom button sits beneath it, delegating clicks to the native button — giving full control over visual design while maintaining Google's security guarantees.

### Error Handling

`parseApiError()` in `AuthForm.tsx` translates every possible error code into a human-readable message:
- `FETCH_ERROR` → "Backend may be spinning up on free tier, wait ~40s"
- `409` → "Email already registered"
- `401` → "Invalid credentials"
- `403` → "Account blocked"
- `500` → "Server error"

### Custom Animations

| Animation | Purpose |
|-----------|---------|
| `animate-fade-up` | Cards and content entering the viewport |
| `animate-scale-in` | Modals and dialogs appearing |
| `animate-fade-in` | Overlays and subtle transitions |

### Responsive Strategy

Every view is fully responsive with three breakpoints:
- **Mobile (<sm)**: Card-based layouts, stacked elements, hidden table columns
- **Tablet (sm–lg)**: Two-column grids, condensed spacing
- **Desktop (≥lg)**: Full multi-column layouts, sidebars, expanded data tables

The Watchlist is a good example: mobile shows stacked metric cards per stock; desktop shows a full HTML `<table>` — implemented with CSS only, zero JS breakpoint detection.

### Accessibility

- ARIA roles on interactive elements (`role="tab"`, `role="switch"`, `role="tablist"`, `role="dialog"`, `role="alert"`, `role="status"`)
- `aria-selected`, `aria-checked`, `aria-pressed`, `aria-label` attributes throughout
- `aria-modal` on all modal overlays
- SVG `role="img"` with `aria-label` on ConfidenceRing
- Keyboard navigation support (`Escape` closes modals)

### Skeleton Loading

A universal `<Skeleton>` primitive (`bg-white/5 animate-pulse rounded`) is composed into page-specific loading states that exactly match the shape of the loaded content — preventing layout shift.

## 🔧 Environment Variables

```bash
# .env
NEXT_PUBLIC_API_URL=http://localhost:5000
```

The `getApiBaseUrl()` utility in `baseApi.ts` normalizes this URL — it strips trailing slashes and removes any `/api/v1` or `/api` suffix, so the value can be set in any common format without breaking requests.

> **Note on Twelve Data**: The API key is configured **on the backend only**. The frontend never touches financial API credentials — it simply consumes the normalized, provider-agnostic response from the backend. When the backend has no key configured or the quota is exhausted, the `dataSource` field switches to `"simulated"` and the frontend renders the warning badge automatically.

## 🧩 Notable Implementation Details

### `ConfidenceRing` — Pure SVG Custom Component
```tsx
// No library. Full accessibility. Animated via CSS stroke-dashoffset.
// The --c CSS variable holds the circumference, computed from the radius.
strokeDashoffset={circumference * (1 - value / 100)}
```

### Dual-Layer Google Sign-In Button
The native GSI button is rendered in a hidden overlay (`opacity-0 z-10`) while a fully styled custom button sits behind it. Clicks on the custom button are delegated to the hidden native button — combining design freedom with Google's security infrastructure.

### Middleware Route Rewrites
```ts
// /dashboard → /user/dashboard (transparent to the user, correct for Next.js)
// /stocks/AAPL → /user/stocks/AAPL
// Security headers injected on every request
```

### Type Safety — Single Source of Truth
All types live in `src/types/index.ts`. `src/redux/type.ts` is a pure re-export barrel — no duplication, no drift. Any change to `Stock`, `AlertItem`, or `AuthUser` propagates instantly across the entire codebase.
